# 《升维 · Ascend》完整性验证报告

> 验证版本：v1.7.36（`1e6deb9`，与 GitHub Pages 线上版一致）
> 验证日期：2026-08-13
> 验证方式：8 项自动化审计脚本 + Playwright 核心闭环实测（0 控制台错误）+ 核心源码审查（game.ts / duel.ts / abilities.ts / story.ts / team-academy.ts / leadership-model.ts）

## 一、总体评分

| 维度 | 得分 | 依据 |
|---|---|---|
| **产品层** | **7.5 / 10** | 核心闭环跑通、QA 基建顶尖、存档工程成熟、内容量巨大 |
| **体验层** | **6 / 10** | 机制新颖、反馈丰富、重玩价值高，但主题割裂、视听质感存疑、情感钩子弱 |
| **综合** | **6.5 / 10** | 功能上"完整"，体验上尚未"优秀" |

## 二、最大亮点（当前做得最好的地方）

1. **工程化 QA 基建是一流的**。8 个审计脚本（内容/领导力/学院/系统/无障碍/音乐/数值平衡/i18n）全部 PASS、0 issue、0 控制台错误；`smoke.mjs` 用系统 Edge 免浏览器下载，能从建档一路跑到 AI 1v1 + 本地双人 + 教练工作坊。这是非常完整的游戏项目自测体系——"能不能上线"这个问题，它已经用代码回答了。

2. **存档与成长系统是生产级水准**。`game.ts` 的存档层有 normalize（字段清洗）+ migrate（版本迁移，保留未知字段）+ sessionStorage 备份 + 损坏档标记恢复 + 三角色独立槽 + 云冲突"时间戳+内容哈希"双校验 + 存档导出/复制链接。这是很多商业项目都没有的健壮度。

## 三、短板（20 条，按严重程度排序）

### 🔴 P0 — 发布前必须解决

**1. `App.ts` 是 10300 行的巨型单体文件**
所有 UI 界面 + 状态路由挤在一个文件里。任何改动都要在万行文件里定位，改动风险极高。

**2. 三套能力模型并存，玩家认知混乱**
十项能力谱系（识人/用人/…/协同沟通）驱动主线与段位；"领导力五维模型"（信服力/共情力/决断力/格局力/韧性值）驱动报告页；团队学院另有"四维影响力"（信任力/连接力/战略力/传承力）。实测截图里同时出现"综合能力值 12"和"五维全 Lv.1"，玩家不知道"我的能力到底是哪套"。

**3. 源码里有 GBK 编码乱码**
`game.ts`、`duel.ts` 多处中文注释变乱码（如 `鍥炲悎瓒呮椂` = "回合超时"）。不影响运行但反映历史编码事故，且污染代码可读性。

**4. 主题叙事三层割裂**
核心是"权经九章 + 自适应领导力（Heifetz）"的严肃职场叙事，但地图被包装成"四大文明·藏宝图 / 古埃及·太阳历书"的探险主题，同时又有"领导力游戏中心"的休闲模块。三套气质各说各话，玩家难形成统一心智。

### 🟠 P1 — 影响体验的关键项

**5. 首屏构建产物 `ui` chunk 达 909KB**（gzip 288KB），移动端弱网首屏慢。build 已发出 chunk 超限警告。

**6. 重构不彻底，存在多版本并存**：`duel.ts` vs `duel-v2.ts`、`audio.ts` vs `audio-v2.ts`、`scenario-shell.ts` vs `scenarioShell.ts`（大小写差异）、`theme-music.ts` 出现在两个目录。旧版没删干净。

**7. 云端功能是"演示"态**：报告页明示"需在线版与后端才可启用"，账号/云存档/排行榜/自动匹配实际不可用，而这是 PRD 承诺的核心卖点之一。

**8. 移动端文本密度高，真机可读性未验证**（CODEX_HANDOFF 自认的已知风险）。情境页同时塞背景、剧情、情报、修炼公式、教练提示、探秘现场、选项——手机屏大概率拥挤。

**9. WebRTC 跨网络真机未验收**：本地双浏览器通过，但真机 NAT 穿透是另一回事，这是远程对战能否用的前提。

### 🟡 P2 — 内容与打磨

**10. 内容"大而全"但深度分层存疑**：81 主线 + 108 学院场景 + 5 小游戏，量巨大；但核心体验（18 个主线情境）与扩展内容（63 扩展 + 108 学院）的质量是否同一水准，无真人数据佐证。

**11. 缺真实玩家数据闭环**：`balance-sim.mjs` 存在但纯模拟；没有把真实玩家的决策分布、卡点、流失点回灌进平衡迭代。

**12. 奖励以数字/称号为主，情感钩子弱**：反馈是"+105 契合分 / +3 识人 / 解锁成就"，偏"游戏化数字"，少了"我做的这个决定，会怎样影响一个具体的人"的叙事回响。

**13. 主页信息过载**：10+ 模块入口（主线/1v1/5游戏/能力/报告/试炼/成就/关系图/学院/双人），新玩家 3 秒内难判断"我现在该点哪"。

**14. 程序化视觉/音效质感存疑**：全程序化生成（SVG + Web Audio），风格统一但质感上限低，缺真实美术资产兜底；"藏宝图/古埃及"主题的视觉包装是后加的，与核心严肃叙事气质不符。

**15. `analytics.ts` 仅 32 行**：无留存/流失/关卡通过率监测，无法回答"玩家玩到第几章走了"。

### ⚪ P3 — 长期

**16. 新手引导只有 3 条静态提示**，缺渐进式教学（探秘→选择→反馈的机制靠玩家自己摸）。

**17. 结局/余味依赖单一文本**，缺多感官闭环（回顾蒙太奇、选择后果可视化）。

**18. 认证/段位是"数字证明"**，缺成就叙事感（"认证通过"背后没有可分享的荣誉凭证）。

**19. 三套能力体系导致报告/成长/段位关联不清**（能力值 12 与五维全 Lv.1 的矛盾直接暴露在 UI 上）。

**20. 内容管线缺失**：规模化靠手写 `story.ts`（5045 行）+ `translations.ts`（3290 行），加一个情境要同步改中英/角色变体/理论/情报五处。

## 四、具体建议（按优先级，可执行）

### P0 优先（1-2 周）

| # | 问题 | 为什么 | 怎么做 |
|---|---|---|---|
| 1 | App.ts 万行单体 | 任何改动风险高、不可测 | 按视图拆到 `src/ui/views/`（每个 `data-action` 一个文件），App.ts 只留路由。可先拆最独立的团队学院/领导力游戏/报告页 |
| 2 | 三套能力模型 | 玩家认知分裂 | **明确一套主模型**（建议十项谱系，因主线/段位/1v1 都靠它），五维/四维降级为"该模块的局部进度条"，在 UI 上改名弱化，避免与"能力"混淆 |
| 3 | 编码乱码 | 代码可读性/专业性 | 用脚本批量检测乱码序列，逐个替换回正确中文（注释，不影响逻辑） |
| 4 | 主题割裂 | 玩家难建立统一心智 | 二选一：要么"藏宝图探险"全面贯串（会稀释领导力严肃性），要么**回退藏宝图包装、聚焦"权经 + 情境高尔夫"的严肃调性**。推荐后者——产品定位是高管教练工具，不是冒险游戏 |

### P1 优先（2-4 周）

- **5 性能**：`vite.config.ts` 里对 `ui` 做 manualChunks 或动态 `import()` 拆分（团队学院/领导力游戏天然可懒加载），目标把首屏 chunk 压到 <300KB。
- **6 清理**：删除 `duel.ts`/`audio.ts`/`scenarioShell.ts` 等旧版，统一到 v2 命名。
- **7 云端**：如果后端是卖点，至少把一个最小可用服务（账号+云存档）部署到 Railway/Render 并点亮，否则在 UI 上明确"离线版"而非"演示"。
- **8 移动端**：跑 `test:device-screenshots` 看 720×1280 实况，情境页做信息折叠（默认收起情报/公式，点开才显示）。
- **9 WebRTC**：用两个真机（不同网络）做一次完整对局，记录 NAT 类型与失败率。

### P2/P3（持续）

- **11 真人闭环**：用 `docs/REAL_USER_TEST_KIT.md` 找 5-10 个目标用户（教练/创业者/高潜）实玩，记录第几章流失、哪些选择卡住，回灌数值。
- **12 情感钩子**：在关键情境的反馈里加"这条决策让某个 NPC 发生了什么"的后果句（现有 NPC 关系图可复用）。
- **13 主页减负**：默认只展示"开始主线 / 1v1 / 团队学院"三个主入口，其余收进"更多"。
- **16 引导**：把 3 条静态提示改成第 1 章内嵌的强制教学步骤（探秘→选→看反馈各带一步高亮）。
- **20 内容管线**：把情境数据迁到 JSON/结构化源，脚本生成中英+角色变体，`story.ts` 瘦身为运行时。

## 五、一句话总结

**这个游戏在"能不能跑、会不会崩、有没有内容"上已经是一个完整的作品（QA 全绿、闭环跑通、存档健壮），但它离"完整且优秀"还差一步——把三套能力模型和三套主题气质收敛成一套清晰的心智，以及让 10300 行的 App.ts 不再成为每次改动的心理负担；换句话说，它现在是"一个功能完备的产品"，还不是"一个有明确主张的作品"。**
